# Перенос BrainUp в свой аккаунт Cloudflare

Подготовлен самостоятельный Cloudflare Worker с D1 и Static Assets. Текущий сайт в Sites работает отдельно. Запуск команд ниже сам по себе не переносит живые данные и не меняет адрес Mini App.

## Подключение аккаунта

Нужен Node.js 24+. Выполните `npm ci`, затем `npm run cf:login` и подтвердите официальный вход Cloudflare. Используется OAuth Device Flow без доступного извне localhost-порта. Запрошены чтение аккаунта/пользователя, управление Workers scripts и D1. Wrangler самостоятельно запрашивает обновление сессии. Доступ ко всем продуктам Cloudflare, DNS и биллингу для этого переноса не нужен.

`npm run cf:whoami` проверяет аккаунт. Пароли, токены, коды и конфигурация OAuth не должны попадать в Git, переписку или архив проекта. Временная среда может потерять сессию; в таком случае потребуется повторный официальный вход.

## Новая база и сборка

1. `npm run cf:db:create` — создать `brainup-restore` с binding `DB`, если такой базы ещё нет. Скрипт публикации определяет её UUID по имени в `wrangler.jsonc`.
2. `npm run cf:db:migrate` — применить схему к D1.
3. `npm run cf:check` — собрать и проверить публикацию без отправки Worker. HTML, изображения и музыка размещаются в `dist-cloudflare/public`, сервер — в `dist-cloudflare/server`. Приватные файлы и исходники не входят в публичную статику.

Текущая Sites-сборка остаётся командой `npm run build`. Независимая сборка — `npm run build:cloudflare`. Локальный `npm run cf:dev` использует отдельную локальную D1; она не является копией production.

## Копирование production

1. В текущем Mini App владелец открывает профиль → настройки → «Скачать резервную копию для переноса». Сервер проверяет владельца и сохраняет полное исходное состояние с ревизией и обе таблицы поддержки. Секреты окружения в этот файл не включаются.
2. Перед финальным экспортом установите `MIGRATION_READ_ONLY=true` на **старом** сайте и примените его развёртыванием. Оставьте открытой сессию владельца, скачайте окончательную копию и храните её в закрытом месте. Игровые запросы остановлены; Telegram получает 503 и повторит доставку. Предварительная копия, сделанная до остановки записей, не годится для окончательного переключения.
3. `npm run cf:db:import -- /закрытый/путь/brainup-backup.json`. Скрипт принимает только известный формат, требует пустые таблицы, не перезаписывает существующие данные и проверяет количество записей, ревизию и размер состояния. SQL временно записывается с правами 0600 в игнорируемую `.cloudflare-local`. При ошибке импорта не переключайте приложение; сначала проверьте частично загруженную новую базу.
4. Сохраните исходный бэкап и его контрольную сумму отдельно от репозитория. База `.sites-runtime/preview.sqlite` содержит локальные тестовые данные, использовать её вместо production нельзя.

Обычный просмотр таблиц Sites не способен вернуть большую строку `site_state` целиком. Для переноса используется защищённая выгрузка владельца; обрезанный ответ не считается резервной копией.

## Секреты и публикация

В новом Worker задайте через Cloudflare Secrets (защищённый ввод, без значений в Git):

| Имя | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Тот же бот и проверка подписанных данных Mini App |
| `TELEGRAM_WEBHOOK_SECRET` | Проверка запросов webhook |

Необязательные переменные: `TELEGRAM_SUPPORT_URL`, `TELEGRAM_NEWS_URL`, `TELEGRAM_NEWS_CHANNEL`, `TELEGRAM_START_PHOTO`. Перенесите их текущие значения, если они настроены. На новом сайте `MIGRATION_READ_ONLY` должен отсутствовать либо быть `false`.

В Cloudflare target принимается только подписанная Telegram Mini App identity. Заголовки `oai-authenticated-user-*` игнорируются. При открытии в обычном браузере показывается просьба открыть приложение в Telegram; вход ChatGPT не переносится. Существующие `tg:...` идентификаторы сохраняются вместе с базой, права владельца остаются привязаны к Telegram ID.

`npm run cf:deploy` применяет схему D1, публикует Worker и проверяет открытие публичной страницы. При запуске с чистой базой первый вход создаёт новый аккаунт с нулевым балансом. Ответ 200 на `GET /healthz` означает, что подключены база и оба обязательных секрета. Затем проверьте вход через Telegram, собственный баланс/инвентарь, админку и уведомления. Проверка healthz не подтверждает валидность токена бота; его нужно проверить через Telegram.

## Переключение и откат

Только после проверки переноса поменяйте Telegram webhook на `https://НОВЫЙ-АДРЕС/telegram/webhook` с соответствующим `secret_token`, сохранив pending updates (`drop_pending_updates` не включать). Обновите URL Mini App в BotFather, кнопку меню бота и существующие закреплённые кнопки. Старые сообщения Telegram автоматически не меняют адрес. При необходимости подключите собственный домен к Worker и дождитесь сертификата. Старый `chatgpt.site` адрес Cloudflare не принадлежит.

Не открывайте одновременно запись в обе базы. При откате верните URL и webhook, а перед снятием блокировки старого сайта перенесите назад новые записи, если новая площадка уже принимала действия. Старую базу и площадку сохраните до подтверждённого завершения переноса.
